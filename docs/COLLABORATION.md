# 三人协作与统一接口

本文只定义协作和接口约定，不改变 A1 需求文档中的验收标准。接口未定的项明确标为待确认，不靠实现细节猜。

## 1. 分工

| 分工 | 主要交付 | 不负责 |
|---|---|---|
| 定位与坐标 | D435i/VINS 接入、相机—IMU 外参、相机—Go2 安装外参、机身参考点转换、定位有效性与误差分析 | 不直接向机器人发运动命令 |
| 路径与跟踪 | 目标语义、平滑路径/跟踪算法选型与复用、转向与终点接近、离线验证 | 不直接调用 SportClient 发运动命令 |
| Go2 接口与实验 | 原生 SDK 适配、终端交互、唯一运动命令发送入口、停止失败锁存、CSV 与独立测量 | 不修改定位算法或标定真值 |

先共同确认接口，再各自实现。定位/路径模块只产出数据和速度请求，由接口模块统一发送。

## 2. 统一接口

冻结的数据结构、坐标/单位、`T_base_cam` 方向、变换公式和 `valid` 规则见 [INTERFACE.md](INTERFACE.md)。本节给出协作层面的摘要；若与 `INTERFACE.md` 冲突，以实现和该冻结文档为准，先评审再改。

### 2.1 坐标系与参考点

- `base_link`：固定在 Go2 机身上的坐标系。X 向前、Y 向左、Z 向上；绕 Z 轴左转（逆时针）为正。
- `base_link` 原点：核对后的 Go2 模型 `base` / `trunk` 对应原点。**模型命名和物理位置必须实际确认**，不能仅凭名称认为 `base` 与 `trunk` 是同一点。
- 参考点固定于机身，不随腿部动作重新定义，也不等于运动中变化的全身重心。
- `nav`：任务开始时建立的固定导航参考系。原点为初始 `base_link` 原点的地面投影，X 为初始机身前向的水平投影，Z 竖直向上。建立后不随机器人移动或转向改变。
- 定位重置、重新初始化或参考系不连续后，必须停止任务并重新确认，不能沿用旧 `nav` 坐标目标。

### 2.2 单位与时间

| 量 | 单位/约定 |
|---|---|
| 位置、距离 | m |
| 线速度 | m/s |
| 角度 | rad（终端输入可用 deg，但进入接口前明确换算） |
| 角速度 | rad/s，左转为正 |
| 时间 | s；使用发布端提供的同一时钟域 |
| 时间戳 | 位姿与速度必须可对应到同一时间基准；不得把 Orin、电脑和 bag 接收时间混用而不说明 |

### 2.3 目标语义

- 默认相对目标：`(forward_m, left_m)`，以**接收命令时**的 `base_link` 朝向为准；接收时一次性转换到固定 `nav` 坐标并保持不动。
- 绝对目标：`nav` 中的 `(x_m, y_m)`，作为补充输入方式。
- 两种语义必须使用不同命令或不同字段；不得复用同一命令而隐含不同含义。
- 到达 B 点后前往 C 点，以 B 点接收命令时的机头方向重新确定 C 点；不要求重建底层定位原点。

### 2.4 机身状态输出

定位模块向控制模块提供的状态至少包含：

| 字段 | 含义 |
|---|---|
| `stamp` | 状态时间戳（明确时钟域） |
| `position_m` | `base_link` 原点在 `nav` 中的 `(x, y, z)` |
| `yaw_rad` | `base_link` 的 +X 相对 `nav` +X 的航向，左转为正 |
| `velocity_mps` | **`base_link` 原点**的速度，表达在 `base_link` 中：`vx` 前向、`vy` 左向 |
| `yaw_rate_radps` | 绕 Z 的角速度，左转为正 |
| `valid` | 是否可用于闭环；包含超时、非有限值、跳变/重置判据 |

要求：

- 位置、速度、航向对应同一个参考点；不能用相机光心位置配机身参考点速度。
- 由相机 IMU 位姿转换到 `base_link` 时，平移和旋转都要处理；转弯时速度还要补偿相机 IMU 原点到机身参考点的杠杆臂。
- 定位失效、超时或明显跳变时停止运动任务；不得静默切回原生位置反馈继续走。
- 姿态横滚/俯仰和步态由原生运动控制处理；首期导航只使用航向和水平位置。

### 2.5 运动命令接口

路径与跟踪模块向 Go2 接口模块输出请求：

| 字段 | 含义 |
|---|---|
| `stamp` | 请求时间 |
| `vx_mps` | 机身前向速度，前进为正 |
| `vy_mps` | 机身左向速度；A1 正常跟踪应尽量为 0，不以侧移作为常规到点手段 |
| `vyaw_radps` | 机身转向角速度，左转为正 |
| `stop_request` | 请求停止；停止后不得因旧任务自动恢复运动 |

Go2 接口模块负责限幅、10 Hz 重发、状态超期检查、`StopMove` 和停止失败锁存。路径模块不持有 SDK 客户端。

## 3. 分支与 PR

- 默认分支保持可构建；功能/实验使用独立分支。
- 每个 PR 说明改了什么、如何离线验证、是否触碰实机边界、是否改变配置语义。
- 至少一名其他成员审阅后再合并；不在共享分支强制改写历史。
- 不把单次实验结论直接写成生产配置；失败和异常记录保留。
- 原始 bag、视频、模型、构建产物、第三方源码和安装树不进入普通 Git 历史。

## 4. 实机安全边界

- 实机只允许**一个**运动命令发送入口；其他工具只能订阅状态或只读查询。
- 停止失败锁存必须保留：`StopMove` 失败后本会话拒绝运动命令，即使后续返回 0 也不自动恢复。
- 程序退出、`StopMove` 返回 0、速度指令为零都不证明机器人实际停住，现场必须人工确认。
- 电脑掉电、进程强杀、断网时清理回调不能保证执行；不进行未经安排的断线/故障试验。
- 遥控与电脑命令的优先级尚未验证为独立急停；现场保持遥控器在手并使用已核对的停止方式。
- 首期只在平坦开阔区域低速验证，不声称自主避障。

## 5. 数据、记录与收尾

- 原始录包、视频、异常结果和失败记录保留；不因结论不好而删除或改写。
- 每次运行记录实际命令、参数、退出码、CSV/日志路径和测量方法。
- 运行结束关闭本次启动的相机、VINS、记录器和运动工具，核对残留进程；不关闭他人的会话或 Unitree 原生服务。
- 独立测量使用卷尺/地面标记；定位估计进入容差不算 5 cm 验收通过。

## 6. 待共同确认

- `base_link` 原点的实际物理位置和测量基准（模型命名已冻结，物理点待现场确认；见 `docs/MEASUREMENT_CHECKLIST.md`）。
- 相机到 Go2 机身的安装变换及计算部署位置（`T_base_cam` 未实测）。
- 定位状态的具体传输方式（进程内结构已冻结，ROS 话题或共享内存尚未确定）。
- 路径跟踪算法的最小集成方式、首期速度/距离和验收次数。
- 新仓库名称、位置和三人权限。
